Why mcptoon is a CLI, Not Another Daemon Proxy

MCP was designed under the assumption that every capability must be a running daemon server that every agent explicitly mounts. That creates painful configuration drift.

Zero Overhead Architecture

The Resident Proxy Trap

  • Must hand-craft separate JSON configurations for Claude, Cursor, Windsurf, Cline...
  • Every agent launch requires restarting background proxies or fighting port conflicts
  • Dumps full parameter definitions into context before you even type your prompt
  • Adding a new tool means manually updating multiple config files all over again

The mcptoon CLI Architecture

  • Zero Config for 42 CLI/IDE Agents: Claude Code, Cursor, Codex, Zed just execute mcptoon call
  • One Single Config File: Add a tool or skill once via mcptoon; all agents immediately share it
  • No Daemons, No Memory Footprint: Pure Python standard library CLI (363KB). Executes and exits
  • Universal Fallback (61 GUI Apps): Non-shell GUI clients connect via a single lightweight mcptoon serve bridge

Frequently Asked Questions

Why is a CLI better than running a background proxy?

A background proxy still requires each AI agent to be manually configured with hostnames, ports, and headers. A CLI leverages the universal capability every coding agent already possesses: terminal execution. Agents call mcptoon call directly without any per-agent JSON setup, avoiding background memory leaks and port collisions entirely.

How does mcptoon handle both MCP tools and Agent skills?

mcptoon provides unified governance for both: for MCP tools, it indexes schemas into names-only pointers (cutting token cost 99.2%) and pulls parameters on-demand. For skills, instead of dumping hundreds of SKILL.md files into agent prompt memory, it installs a 39-token resident pointer and uses an ultra-fast offline BM25 router to pull only the matching skill playbook when needed.

Do I have to re-configure all my AI agents?

No. mcptoon quickstart automatically detects your installed agents (Cursor, Claude Code, Windsurf, Cline, etc.) and MCP servers, creating a single unified configuration and distributing the official /mcptoon skill into all of them. Add or remove tools in one place, and all agents immediately sync.

Does mcptoon send any telemetry or code to remote servers?

Never. mcptoon is 100% local, open-source under Apache-2.0, and contains zero dependencies. All indexing, token counting, and routing run entirely on your local machine.
